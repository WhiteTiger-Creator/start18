A failed telemetry migration stalled the basin's release schedule. It truncated the authoritative gauge series at `/app/data/gauge_readings.json` and left the release scheduler at `/app/workflow/schedule_releases.go` allocating water under draft rules the basin board later reversed. Nothing the scheduler produces can be trusted until that series is rebuilt. A pre-migration snapshot at `/app/data/gauge_snapshot_pre_migration.json`, a journal of the changes the migration posted after it at `/app/data/telemetry_journal.json` and the sensor datum table at `/app/data/sensor_datum.json` survive beside the truncated file. How the two combine, which reading a change names, what a retraction does, what a later restoration brings back, how a raw stage is brought onto the basin datum and the order of the result are decisions the basin board has already taken and recorded in `/app/incident/basin_governance_log.md`; the series is rebuilt in place at `/app/data/gauge_readings.json`, in the shape the contract's `reconciled_inputs` gives it, before the scheduler is worth running.

Then restore the scheduler at `/app/workflow/schedule_releases.go`, a Go program built with the toolchain installed here. It stays one `package main` in that one file and is compiled from that file alone, so a helper split into a sibling source beside it never reaches the build. Preserve its `--input` and `--output-dir` options and their defaults; the reservoir register, the rights register and the operating policy are always read from their fixed absolute paths under `/app/data`, and `--input` selects the gauge series only. `/app/docs/release_contract.json` is the output contract: paths, schemas, required-field lists, container shapes and sort orders. It says nothing about how any value is derived. Reconstruct that from `/app/incident/basin_governance_log.md`, mostly routine operations minutes, where the later dated decision governs. A run writes exactly three files, `summary.json`, `release_schedule.json` and `curtailment_queue.jsonl`, into the directory `--output-dir` names -- `/app/output` where the flag is left at its default, and the directory it is handed otherwise -- so anything an earlier run left in that directory is cleared rather than passed off as this run's output; clear the contents, since the run does not own the path it writes into, and a run writes only inside that directory and nowhere else. The contract states the scale a run is expected to handle. Derive every value from the operational inputs: correct against an alternate gauge series, identical across reruns. The recovery sources and the rule documents are read rather than rewritten, so the pre-migration snapshot, the telemetry journal, the sensor datum, the reservoir and rights registers, the operating policy, `/app/docs/release_contract.json` and the governance log all come back byte for byte unchanged, and the frozen snapshot `/app/workflow/.schedule_releases.original.go` is left exactly as it is.
